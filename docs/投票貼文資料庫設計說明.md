Easy Social 投票貼文資料庫設計說明

本設計用於 Easy Social 的投票貼文功能。使用者可以建立一則包含 2 至 4 個選項的投票貼文，其他登入使用者可以選擇其中一個選項投票。資料庫設計以既有的 post 貼文表為基礎，再新增 poll、poll_option、poll_vote 三張資料表，用來儲存投票本身、投票選項與使用者投票紀錄。


一、資料表結構

1. user 資料表

user 為既有使用者資料表，本功能不修改其結構。投票貼文會透過 post.author_id 關聯到發文者，投票紀錄會透過 poll_vote.user_id 關聯到投票者。

主要欄位：
id：INTEGER，主鍵。
username：VARCHAR(40)，不可為空，唯一，使用者名稱。
email：VARCHAR(255)，不可為空，唯一，電子郵件。
password_hash：VARCHAR(255)，不可為空，密碼雜湊值。
bio：VARCHAR(280)，不可為空，個人簡介。
created_at：DATETIME(timezone=True)，不可為空，建立時間。


2. post 資料表

post 為既有貼文資料表。投票貼文仍然是一種貼文，因此投票問題文字會存放在 post.body，並使用 is_poll 標記該貼文是否為投票。

主要欄位：
id：INTEGER，主鍵。
body：TEXT，不可為空。一般貼文為內容文字；投票貼文為投票問題。
media_filename：VARCHAR(255)，可為空，媒體檔名。
media_type：VARCHAR(20)，可為空，媒體類型。
is_poll：BOOLEAN，不可為空，預設 false，表示是否為投票貼文。
created_at：DATETIME(timezone=True)，不可為空，貼文建立時間。
author_id：INTEGER，不可為空，外鍵連到 user.id。
repost_of_id：INTEGER，可為空，外鍵連到 post.id，表示轉發來源。

限制：
貼文必須至少符合下列其中一項：body 有內容、media_filename 有值、repost_of_id 有值，或 is_poll 為 true。


3. poll 資料表

poll 代表一則投票本身。每一則投票都必須對應到一篇 post，且一篇 post 最多只能有一則 poll。

欄位：
id：INTEGER，主鍵。
post_id：INTEGER，不可為空，外鍵連到 post.id，且必須唯一。
created_at：DATETIME(timezone=True)，不可為空，投票建立時間。

限制：
post_id 設為 UNIQUE，確保一篇貼文只能對應一則投票。


4. poll_option 資料表

poll_option 儲存投票選項。一則投票會有 2 至 4 個選項。

欄位：
id：INTEGER，主鍵。
poll_id：INTEGER，不可為空，外鍵連到 poll.id。
label：VARCHAR(200)，不可為空，選項文字。
position：INTEGER，不可為空，選項顯示順序，範圍為 0 到 3。

限制：
poll_id 建立索引，以便查詢某則投票的所有選項。
poll_id 與 position 組合必須唯一，避免同一則投票內選項順序重複。
position 必須大於等於 0 且小於 4。


5. poll_vote 資料表

poll_vote 儲存使用者投票紀錄。每一筆資料代表某位使用者在某則投票中選擇了一個選項。

欄位：
id：INTEGER，主鍵。
poll_id：INTEGER，不可為空，外鍵連到 poll.id。
option_id：INTEGER，不可為空，外鍵連到 poll_option.id。
user_id：INTEGER，不可為空，外鍵連到 user.id。
created_at：DATETIME(timezone=True)，不可為空，投票時間。

限制：
poll_id、option_id、user_id 建立索引，以加速投票統計與查詢。
user_id 與 poll_id 組合必須唯一，確保同一位使用者對同一則投票只能投一次。


二、資料表關聯性

user 與 post：一對多。一位使用者可以發佈多篇貼文，post.author_id 連到 user.id。

post 與 poll：一對一，可選。一篇一般貼文沒有 poll；一篇投票貼文會對應一筆 poll，poll.post_id 連到 post.id。

poll 與 poll_option：一對多。一則投票包含多個選項，poll_option.poll_id 連到 poll.id。

poll 與 poll_vote：一對多。一則投票可以有多筆投票紀錄，poll_vote.poll_id 連到 poll.id。

poll_option 與 poll_vote：一對多。一個選項可以被多位使用者選擇，poll_vote.option_id 連到 poll_option.id。

user 與 poll_vote：一對多。一位使用者可以參與多則投票，poll_vote.user_id 連到 user.id。


三、主要資料完整性規則

1. 投票貼文必須有問題文字，也就是 post.body 不可為空。

2. 每則投票必須有 2 至 4 個選項。

3. 同一則投票內的選項順序不可重複，因此 poll_option 使用 poll_id 與 position 的唯一限制。

4. 同一位使用者對同一則投票只能投一次，因此 poll_vote 使用 user_id 與 poll_id 的唯一限制。

5. 每一筆投票紀錄都必須指向有效的投票、有效的選項與有效的使用者。

6. 投票結果可由 poll_vote 依 option_id 分組統計票數，再以「選項票數 ÷ 總票數 × 100」計算百分比。


四、設計摘要

本設計將投票貼文視為 post 的延伸類型，使用 is_poll 區分一般貼文與投票貼文。poll 表保存投票與貼文的一對一關係，poll_option 表保存選項內容與排序，poll_vote 表保存使用者投票紀錄。透過外鍵、唯一限制與欄位檢查，可以確保投票資料與使用者、貼文、選項之間保持一致，並避免重複投票或選項順序錯誤等問題。
